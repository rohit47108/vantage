# Linked mosaic pixel brightness traces

Checked November 15, 2026. This is an implemented visual-context workflow, with separate scientific and public-release evidence. It does not complete the full product goal or validate source photometry from a mosaic.

## Documented facts and live observations

The [official IRSA HiPS cube notebook](https://caltech-ipac.github.io/irsa-tutorials/spherex-hipscube/) supplies the cube path, named extensions and wavelength indexing. It explicitly restricts its extracted brightness trace to visualization and points scientific measurements to native-exposure spectrophotometry. The notebook and actual spectral table define 102 ascending layers: six detectors with 17 channels each; zero-based layers 50 and 51 are blank dichroic channels. Strong line emission can produce mosaic striping. A high point in this plot is not evidence of a validated line measurement.

The live [Npix445 cube](https://irsa.ipac.caltech.edu/ibe/data/spherex/dr1/hips5_cube/hips_20261026/Norder5/Dir0/Npix445_cube.fits) has 320,909,760 bytes and strong ETag `"9bbeb7365d2bb8fdfd0842b729b0cf32"`. Its retained headers are in `fixture.json`: primary processing version 7.2.0, UTC time scale, ICRS IMAGE coordinates, IMAGE/NHITS/FLAGS shapes `(102,512,512)`, IMAGE unit MJy/sr, 32-bit integer hit/flag storage, SPECTRAL_CHANNELS and WCS-WAVE tables. There is no variance extension in this tested cube. Its primary acquisition interval is 2025-08-19 23:48:47.813 through 2026-02-22 13:12:40.649 UTC. This interval describes the contributing mosaic data, not a dated measurement for each selected pixel or wavelength.

HEAD returned length and modification time but omitted ETag. GET Range returned HTTP 206, exact Content-Range and ETag. A deliberately wrong If-Match did **not** prevent a 206 response in the recorded probe. Consequently the implementation checks a strong ETag and object size on **every** range response. It does not assume this server enforces If-Match. See `artifacts/spectral-trace-versioned-range-probe.json` and `artifacts/spectral-trace-range-probe.json`.

## Implemented method and bounds

`backend/range_reader.py` provides a seekable, read-only, fixed-host stream for [Astropy FITS sections](https://docs.astropy.org/en/stable/io/fits/usage/cloud.html). It checks [RFC 9110 entity-tag syntax](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3), rejects weak/malformed/changing tags, redirects, ignored ranges, inconsistent extents, compressed HTTP bodies and truncated/oversized responses. Defaults: 16 KiB blocks, at most 64 cached blocks, 8,000,000 transferred bytes, 400 requests, 180-second sampling deadline, 2 MB maximum individual read, 8/20-second connection/read timeouts, and cancellation checks between responses and chunks. These are engineering resource limits, not archive guarantees. A network read can finish after the deadline; the next block check terminates sampling.

`backend/spectral_trace.py` maps the **saved display pixel** through its TAN WCS to ICRS, then uses the native tile WCS and the same nearest-pixel rounding as image rendering. It reads IMAGE, NHITS and FLAGS sections in six 17-channel chunks. It validates the supported processing version, reference systems, units, shape, blank definition and every detector/channel/central-wavelength/bandwidth value against the approved metadata. New unsupported products fail closed. Signed FITS flag words are preserved as unsigned 32-bit values. Source-information bit 21 alone is allowed; defective or unknown bits receive explicit review markers.

All 102 rows remain present. Blank layers, nonfinite brightness, absent hits, or nonpositive hit counts have missing brightness, never a fabricated zero. Hits are contributing-pixel counts, not inverse variance. No errors, significance, flux-density conversion, upper limit, source identification, aperture correction or line inference are generated. The output explicitly sets `numerical_products_authorized=false` and `uncertainties_available=false`.

The physical `trace_data_id` covers the native pixel, versioned source, channel table and retained sample values. The wrapper product ID additionally covers the original display plane/pixel and requested position. Thus different display contexts can reference the same physical trace without losing where the user clicked. Existing published manifests are returned byte-for-byte; timings are not rewritten under the same ID. The three scientific downloads have recorded SHA-256 values. ECSV includes MJy/sr and µm units, integer hits/flags, missing-value masks and source/request metadata. CSV is a convenience table; JSON retains the complete byte-range provenance. SVG contains points without invented error bars or lines through missing channels.

## API and browser contract

1. Open `GET /v1/spectral/plane?ra=60.8109955&dec=51.3404038&fov_arcmin=30&layer=62` to obtain a saved image ID. The current browser grid is 160 by 160.
2. Submit `POST /v1/spectral-traces` with JSON `{"plane_id":"<64 lowercase hex>","x":80,"y":80}`. Coordinates are zero-based native array indices of the displayed grid; the canvas flips only its displayed vertical axis. A missing plane or out-of-bounds pixel is rejected before archive work.
3. Poll the returned `status_url` under `/v1/analysis/jobs/`. Stages report queueing/opening and channel chunks. Cancel with DELETE on the same URL. The shared persistent two-worker queue applies its existing admission/deduplication/recovery policy.
4. Fetch the completed immutable `/v1/products/<id>` manifest; use its export URLs for `trace.ecsv`, `trace.csv`, and `trace.svg`.

The chart, channel table, wavelength slider and image are linked in monochrome and false color. A crosshair and keyboard arrow movement expose the selected display pixel. A wavelength change keeps the point and trace; a new point/field clears them and aborts local restoration/polling. Switching away does not silently cancel another client’s shared server job. Explicit cancellation remains available. Complete jobs and result links restore through `trace`/`trace_job` and `wave_x`/`wave_y` URL parameters. Restoration rejects mismatched field, field size, grid or pixel. A completed mismatched job becomes an actionable terminal error, not an endless reconnect loop. The Measure action carries the clicked ICRS coordinate into the native-source form and returns to the same wavelength view; it does not assert that this pixel contains an isolated source.

## Actual validation and limits

`fixture.json` and `native-ranges.npz` retain **exact raw bytes**, not a reconstructed FITS cube: 311 HTTP response blocks totaling 5,091,776 decoded bytes, compressed to 1,824,776 bytes, with per-block and archive hashes. They include the needed headers/tables and all 102 samples of each named pixel array. `tests/range_fixture.py` refuses uncaptured ranges and verifies those hashes. `tests/test_spectral_trace.py` compares all 102 brightness/hit/flag values against this retained reference; a separate recorded API check verifies equality to the independent November 14 probe as well. `tests/test_spectral_trace_jobs.py` exercises the queued product, restored result and export hashes/units/masks. `tests/test_range_reader.py` covers actual Astropy section reads and invalid version/range/budget/cancellation conditions.

The actual browser-requested reference trace completed in 34.4486 seconds, with 311 requests and 5,091,776 bytes, retaining 100 valid brightness samples and two blank channels. The default even display grid maps pixel `(80,80)` to ICRS `(60.80849418275816,51.3419662733663)` and native tile pixel `(240,212)`; it is not exactly the nominal field center. All 102 sample arrays match the retained native reference, and displayed layers 0, 50 and 62 match the trace value/hits/flags exactly. The cached submit-plus-status round trip took 0.0669 seconds locally. These are measured examples, not performance guarantees. See `artifacts/spectral-trace-live-product.json` and `artifacts/spectral-trace-live-api.json`.

Browser tests cover actual job submission, chart/table/image linkage, two blank channels, ECSV download, URL restore, return from native measurements, keyboard pixel changes, mobile overflow and automated WCAG checks. Separate transport-failure/cancellation and stale-result tests deliberately alter only failed/job transport states; successful brightness data remain authentic. Public-release status and final suite counts belong in `tasks/product-evidence.md` and `IMPLEMENTATION_STATUS.md` after verification.

No general all-sky throughput, calibration accuracy, PSF homogenization, source completeness, line-detection accuracy, time variability or precision source spectrum is established by this trace. Broader field navigation and durable public scientific hosting remain separate requirements.
