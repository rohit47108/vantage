## Live service behavior and bounds

`service-probe.json` records actual query URLs, status and failure details. `gaia_gator.xml` and `wise_gator.xml` contain actual M101 catalog responses. The `gaia.xml` / `wise.xml` files are retained **HTTP 502 error documents from TAP probes**, not catalog data. `gaia-full.xml` / `wise-full.xml` are **VOTable errors**, demonstrating Gator's output limit; filenames do not indicate a full successful result.

Both IRSA TAP spatial queries and the ESA TAP connection failed at this checkpoint. Gator succeeded for both catalogs and is the selected adapter. No availability claim is made for the failing alternatives.

Gator `outrows` is an error threshold, not guaranteed truncation. Exceeding it produced HTTP 200 with `QUERY_STATUS=ERROR` and “Exceeding output table size limit”. The adapter must never interpret this as an empty or complete catalog. It can halve the radius at most six times and records the reduced search as limited. When a dense Gaia cone is reduced, a supplemental query searches the original cone for `pm>1000` mas/year so high-motion sources retain a path into the display. The response remains explicitly incomplete.

Engineering bounds: 2 simultaneous catalog requests; maximum 4 MB per response; `outrows=5000`; 500 retained sources per catalog, ordered with high-motion entries first then proximity; 24-hour cache; cone radius capped at 0.75 degrees. Gaia padding assumes at most 12 arcsec/year from reference epoch 2016, plus a two-arcsecond margin. This bound is a contextual search policy, not a completeness theorem. Reduced/capped/row-limited results are visibly labeled limited. Browser opacity, layer visibility, exact query URLs and all retained source records are exported with the sequence.

Candidate associations compare Gaia's angular model at each WISE source's W1 mean MJD, using a two-arcsecond angular threshold. The epoch is approximate; observer parallax is omitted. Many-to-many candidates are retained, at most 500. The API exposes the cap, query limits, source queries and incomplete status. Only retained sources visible in at least one SPHEREx frame are considered. This is a review aid, not a probabilistic or complete cross-identification catalog.

## Validation and scientific limits

`python -m scripts.validate_surveys` checks real M101 and Barnard field catalog responses against an independent analytic gnomonic projection. Gaia positions are also independently transported with Astropy, without the omitted distance/RV terms. The predeclared tolerance is 1e-4 displayed pixels. Actual maximum error was 2.691e-7 pixels for Barnard Gaia; the other three cases were below 6e-10 pixels. Barnard's retained Gaia source `4472832130942575872` has total proper motion 10393.349 mas/year and is included by the padding/retention policy. M101 returned 355 Gaia and 203 WISE entries within the frames; Barnard returned 500 Gaia and 198 WISE entries. Gaia queries were limited, as stated in the UI.

This establishes coordinate transport and drawing-grid agreement for the stated model. It does **not** measure absolute astrometric alignment against SPHEREx centroids, observer parallax, perspective effects, catalog truth, source identity or survey completeness. The source-selection panel and exported metadata retain these distinctions. AllWISE context satisfies the catalog integration path; no WISE image-layer implementation is claimed.

The ten survey tests cover authentic schemas/IDs, independently checked angular motion at a coordinate wrap/pole, frame WCS mapping, missing projections in tracked views, candidate epochs, explicit caps, Gator error handling, resolver validation/redirect restrictions and graceful API failure. Four browser tests cover real marker hit selection after pan/zoom, actual frame epochs/A-B inspection, independent layer requests, opacity/share/export, accessible tables and mobile keyboard controls, actual name resolution and recovery after catalog/name failures.

The supplemental `constraints=pm>1000` query was also live-tested in the Barnard cone: it returned exactly source `4472832130942575872`, with total motion above 10,000 mas/year. Its actual VOTable and URL/hash record are retained as `barnard-fast-motion.xml` and `fast-motion-probe.json`; the offline schema test checks this authentic result.

An initial browser run found a non-focusable horizontally scrolling candidate table and a disclosure target smaller than WCAG 2.2's 24-pixel requirement. The table now has keyboard focus and the summary has a 44-pixel target. The rerun passed all four tests. The mobile open-controls timeline is in document flow so it does not cover source metadata.
